# 빠짐없이

내가 받을 수 있는 것을 기록하고 판정하는 서비스의 시연용 프로토타입입니다.

## 파일 구조

```
index.html      화면 틀과 랜딩
app.js          화면 로직
data/sources.js 출처 데이터베이스 (83개 · 읽은 내용 347줄 저장)
data/rules.js   제도 규칙 데이터베이스 (15개 분야 93건)
data/people.js  페르소나와 역할 데이터베이스 (10명)
deploy.bat      배포 (파일 수정 후 더블클릭)
```

## 데이터 수정하는 법

**제도를 추가하거나 조건을 고칠 때** — `data/rules.js`

```js
{n:'제도 이름', where:'신청처', visit:'center',
 f:c=> c.age>34 ? NO('만 34세 초과')
     : OK('월 20만','요건 충족', 60, '추첨')}
```

- `c` 는 그 사람의 사실 정보입니다 (`c.age`, `c.home.incomeRate`, `c.biz.years` 등)
- `OK(금액, 사유, 지급방식, 집계값)` / `NO(사유)` / `LOST(금액, 사유, 집계값)` / `CHK(금액, 사유)`
- **선정 가능성 % 는 없습니다.** 근거를 댈 수 없어 2026-09-08에 전부 걷어냈습니다
- **집계값**은 화면 상단 합계에 들어가는 숫자입니다. 단위는 만원이고 생략하면 합계에서 빠집니다
  - `{y:240}` 해마다 반복 (월 20만 × 12개월)
  - `{once:200}` 한 번만 받는 금액
  - `{cap:7000}` 대출 한도 · 받는 돈이 아니라 따로 셉니다
  - `{max:10000}` 선정돼야 받는 최대 사업비 · 확정 금액이 아니라 따로 셉니다
- 새 제도를 넣을 때 집계값을 빼먹으면 화면에는 뜨지만 합계에 안 잡힙니다
- `visit` 은 `center` `bank` `office` `company` `online` 중 하나이며 방문 묶음에 쓰입니다

**사람을 추가할 때** — `data/people.js` 의 `CTX`

```js
k:mk({name:'이름', sub:'설명', age:33, region:'서울',
  work:{on:true, sme:true, insured:900},
  home:{rent:true, deposit:3000, incomeRate:120}})
```

`mk()` 가 나머지 항목을 기본값으로 채우므로 **달라지는 것만** 적으면 됩니다.

## 출처 확인 이력 — 여기에 계속 쌓습니다

각 제도에 `chk` 를 붙이면 화면의 해당 항목에 **확인 날짜와 출처 링크**가 뜹니다.
`chk` 가 없으면 **'출처 미확인'** 으로 표시되고, 화면 상단에 확인 비율이 나옵니다.

```js
{n:'두루누리 사회보험료', type:'cash', where:'근로복지공단', visit:'online',
 chk:{d:'2026-09-08', src:'근로복지공단 두루누리', u:'https://insurancesupport.or.kr/durunuri/intro.php'},
 f:c=> ...}
```

- `d` 확인한 날짜 (YYYY-MM-DD) — 화면에 그대로 표시되므로 오래되면 눈에 띕니다
- `src` 출처 이름 — 기관 자료를 우선으로 씁니다
- `u` 링크 — 사용자가 직접 눌러 확인할 수 있어야 합니다
- `lvl` **확인 수준**. 세 단계로 화면 표시가 달라집니다
  - 생략 = **금액과 요건까지 대조함** → 초록 "확인 2026-09-08 · 출처"
  - `lvl:'org'` = **소관 기관만 확인** → 주황 "금액과 요건은 아직 대조하지 않았습니다"
  - `chk` 자체가 없음 → 주황 "출처 미확인"

`lvl:'org'` 를 `lvl` 없이 승격시키려면 **실제로 수치를 대조한 뒤에만** 지우세요.
기관 홈페이지 링크만 붙이고 승격시키면 확인하지 않은 값이 확인된 것처럼 보입니다.

**제도를 고칠 때마다 `chk.d` 를 그날 날짜로 갱신하세요.** 금액만 바꾸고 날짜를 두면
확인하지 않은 값이 확인된 것처럼 보입니다.

`CHECK_COUNT` / `CHECK_LATEST` 는 `data/rules.js` 끝에서 자동 계산됩니다.

## 선정 가능성(odds)을 없앤 이유

전에는 `OK()` 세 번째 인자가 선정 가능성 %였습니다. 두 가지가 틀렸습니다.

**1. 확률 개념이 안 맞는 자리에 붙어 있었습니다.**
93건 중 72건은 요건을 맞추면 지급되는 이분법인데 "여권 갱신 99%",
"소득세 감면 97%" 같은 숫자가 붙어 있었습니다. 확률이 아니라 자신감의 표현이었습니다.

**2. 경쟁 선발형에서는 같은 화면의 경쟁률과 모순됐습니다.**

| 제도 | 표시 경쟁률 | 그 경쟁률의 기저율 | 표시했던 odds |
|---|---|---|---|
| 예비창업패키지 | 49 : 1 | 2% | 38% |
| 초기창업패키지 | 9 : 1 | 11% | 52% |
| 창업성장 R&D | 7 : 1 | 14% | 47% |

### 대신 쓰는 것 — base 와 bonus

경쟁 선발형(`type:'compete'`)에만 붙입니다.

```js
{n:'초기창업패키지', type:'compete',
 base:{sel:'400개사 내외', comp:null,
       note:'평가 배점은 공개되지 않습니다 · 단계별 60점 미만은 탈락',
       d:'2026-09-08', u:'공고문 링크'},
 bonus:[['CES 2026 혁신상 수상', 2, 'ask'],
        ['기후테크 분야 창업기업', 1, 'ask'],
        ['특허 보유', 2, c=>!!c.biz.ip]],     // 함수면 자동 판정
 f:...}
```

- `base` 의 `sel`/`comp` 는 **모르면 비웁니다.** 비면 화면에 '미확인'이 뜹니다
- `bonus` 세 번째 값이 **함수면 자동 판정**(연동 데이터로 판정), **`'ask'`면 본인 확인 필요**
- 가점표는 공고문 별표를 그대로 옮기고 매년 갱신합니다. `d` 를 그날 날짜로 바꾸세요

### 확률을 만들지 마세요

2026년 초기창업패키지 공고문을 열어보면 평가 항목은 있지만 **배점이 공개돼 있지 않습니다.**
가점도 특허나 창업교육이 아니라 CES 혁신상 같은 대회 수상 이력이라 연동으로 판정할 수 없습니다.
계산할 근거가 없다는 뜻입니다. 화면에 그렇게 적혀 있으니 되돌리지 마세요.

## 상세 뎁스 — 준비물과 절차 (guide)

분야별 상세에서 항목을 누르면 한 단계 아래가 펼쳐집니다.
`guide` 가 없으면 "준비물과 절차를 아직 정리하지 않았습니다"가 뜹니다.

```js
{n:'버팀목 전세자금대출', type:'loan',
 guide:{
   what:'한 줄 설명',
   doc:[['주민등록등본','auto','공공 마이데이터'],
        ['재직증명서','self','회사에서 발급'],
        ['건물 등기사항전부증명서','issue','인터넷등기소 · 700원']],
   how:['1단계','2단계','3단계'],
   warn:'놓치면 안 되는 것',
   time:'심사 2~3주', d:'2026-09-08', u:'출처 링크'},
 f:...}
```

- `doc` 세 번째 값이 **`auto`면 연동으로 자동 제출**, `self`면 본인 준비, `issue`면 발급받아 와야 함
  - 화면 상단에 "준비물 8건 · **4건은 자동 제출** · 4건은 본인이 준비"로 집계됩니다
  - 이게 "서류의 몇 건은 자동으로 낸다"는 주장의 근거이므로, `auto` 로 적을 때는
    실제로 그 연동으로 가져올 수 있는지 확인하고 세 번째 칸에 **어느 연동인지** 적으세요
- `warn` 은 순서를 잘못 잡으면 못 받게 되는 것 위주로 씁니다
- `guide` 에도 `d`/`u` 가 따로 있습니다. 절차는 제도 금액과 별개로 바뀝니다

`GUIDE_COUNT` 가 자동 계산되어 화면 상단에 표시됩니다.

```js
//   금액        왜 판정 못 하는지            무엇이 있으면 판정되는지
```

`NO` 는 **요건을 대조한 결과 미달**이고, `UNK` 는 **필요한 정보가 없어서 결론을 못 낸 것**입니다.
둘을 섞으면 "검토는 끝났습니다"라는 화면의 주장이 거짓이 됩니다.

화면에서 UNK 는 파란 띠와 '판정 불가' 태그로 나오고,
"판정하려면 **○○**가 필요합니다 · 연동으로는 가져올 수 없습니다" 한 줄이 붙습니다.

**연동으로 못 가져오는 정보가 필요하면 NO 로 숨기지 말고 UNK 를 쓰세요.**

### 2026-09-08 4차에서 UNK 로 바꾼 것

## 출처 데이터베이스 (data/sources.js)

**같은 페이지를 다시 열지 않기 위해 만들었습니다.**

전에는 제도마다 `chk:{d, src, u, lvl}` 로 URL 을 직접 박아뒀습니다. 문제가 둘이었습니다.

1. 같은 페이지를 여러 제도가 참조하는데 URL 이 중복으로 들어감
   (채무조정 5건 · 미환급금 6건 · 희망리턴패키지 계열 3건이 각각 같은 출처)
2. **그 페이지에서 무엇을 읽었는지가 저장되지 않음** — 링크만 남아서
   다음에 확인하려면 74개 URL 을 처음부터 다시 열어야 했음

지금은 출처를 한 곳에 모으고 **읽은 문장까지 저장**합니다.

```js
// data/sources.js
'durunuri':{t:'근로복지공단 두루누리', d:'2026-09-08',
 u:'https://insurancesupport.or.kr/durunuri/intro.php',
 facts:['근로자 10명 미만 사업장 · 근로자 월보수 270만원 미만',
        '2021년부터 신규가입 근로자만 지원',
        '고용보험과 국민연금 보험료의 80% 지원',
        '월평균보수 230만원 기준 사업주 월 최대 108,560원',
        '2018년 1월 1일부터 합산 36개월까지만 지원']}

// data/rules.js — 키로만 가리킵니다
{n:'두루누리 사회보험료', type:'cash', chk:'durunuri', f:...}
{n:'버팀목 전세자금대출', chk:'beotimok-2026',
 guide:{..., s:'beotimok-docs'}}   // 절차 출처는 따로 가리킬 수 있습니다
```

**효과**
- 화면의 항목 줄에 "확인 2026-09-08 · 출처 · **읽은 내용 5줄**" 이 뜹니다
- 항목을 펼치면 **"이 판단의 근거 · 출처에서 읽은 내용"** 에 그 문장들이 그대로 나옵니다
- 다음에 다시 확인할 때 **저장된 문장과 비교**하면 무엇이 바뀌었는지 바로 보입니다
- 출처 하나를 고치면 그 출처를 쓰는 제도가 전부 같이 갱신됩니다

**규칙**
- `facts` 를 채우면서 `lvl:'org'` 를 지우는 것이 승격 절차입니다.
  링크만 바꾸고 승격시키지 마세요
- 재확인했으면 `d` 를 그날로 바꾸고 `facts` 도 갱신하세요.
  날짜만 바꾸면 오래된 내용이 최신인 척합니다

`secOf(n)` 이 제도명으로 분야 키를 찾아 아코디언을 엽니다.

## 2026-09-13 9차 — 제출 흐름

`2건 한 번에 제출` 이 아무 데도 가지 않았습니다. 판정에서 끝나는 앱이 됩니다.
`openFlow(names)` → 오버레이 3단계.

| 단계 | 화면 | 담은 것 |
|---|---|---|
| 0 확인 | 제출 확인 · N건 | 건별 **접수 방식**(온라인 접수 / 신고 시 첨부 / 회사 경유 / 은행 접수) · 서류 목록 · 처리 기간 · **어떤 정보가 어디로 나가는지** + 동의 체크 |
| 1 진행 | 제출 중 | 건별 `서류 생성 → 요건 재확인 → 접수` · 기관마다 경로가 달라 한 건씩 |
| 2 완료 | 접수 완료 | 접수번호 · 처리 기간 · **다음에 오는 일 4단계** |

### 설계에서 신경 쓴 것

**'제출' 이 다 같은 제출이 아닙니다.** 창업중소기업 세액감면은 접수하는 게 아니라
종합소득세·법인세 **신고 때 첨부**하는 것입니다. `subKind(r)` 이 `where` 를 보고 구분합니다.
다 '제출' 이라고 쓰면 사용자는 오늘 뭔가 접수된 줄 압니다.

**동의는 목록을 보고 하는 것입니다.** 어떤 연동에서 가져온 자료가 어느 기관으로 나가는지
전부 나열한 뒤에 체크박스가 나옵니다. 체크 전에는 `제출 시작` 이 눌리지 않습니다.

**끝나고 나서가 더 중요합니다.** 완료 화면의 절반은 '다음에 오는 일' 입니다 —
심사·보완 요청 / 결과 통지 / **반려 시 무엇이 걸렸는지 판정에 반영** / 사후관리 의무 알림.
접수로 관계가 끝나면 브로커와 다를 게 없습니다.

**요금 문구.** "저희는 이 제출로 어떤 수수료도 받지 않습니다. 성공보수도 없습니다.
제3자가 대신 접수하지 않습니다."

**접수번호는 시연용이라고 화면에 적습니다.**

개별 항목의 `지금 제출하기` / `한 가지 넣고 제출하기` 도 같은 흐름을 1건으로 엽니다.

### 준비물 흐름 (`openPrep`)

`준비물 챙기고 알림 받기` 도 아무 데도 가지 않았습니다. 제출과 같은 오버레이, 다른 3단계.
**제출은 오늘 끝나지만 준비물은 안 끝납니다.** 그래서 마지막이 접수가 아니라
'언제 다시 알려줄지' 입니다.

| 단계 | 담은 것 |
|---|---|
| 0 준비물 | **본인이 챙길 것만** 추립니다 — 연동으로 채워지는 서류는 건수만 알려주고 목록에서 뺍니다. 건별 `발급 필요` / `본인 보유` 태그와 발급처·비용. 체크하면 하단에 `N / M건 확보`. 창구 방문이 있으면 **같은 곳에서 함께 처리할 다른 건**을 같이 보여줍니다 |
| 1 알림 | 준비물 알림 시점(내일 / 3일 뒤 / 이번 주말 / 일주일 뒤) + 마감 알림. 마감은 날짜를 고르게 하지 않습니다 — 공고에서 역산합니다 |
| 2 저장 | 남은 준비물 목록 · 예약된 알림 · **"준비물이 다 모이면 제출은 저희가 합니다"** |

그룹 단위 버튼(`N건 준비물 정리`)과 항목 단위 버튼이 같은 흐름을 엽니다.

### 1. "수임료 200~300만" 은 회생만 그렇습니다 — 맞습니다

한 문장에 신복위 채무조정과 법원 개인회생을 섞어 놓았고, **신복위도 무료가 아닙니다.**
비용을 셋으로 갈랐습니다.

| | 비용 |
|---|---|
| 신용회복위원회 채무조정 | 상담 무료 · **신청비 약 5만원** |
| 법원 개인회생 · 법원비용 | 채권자 3명 약 22만 ~ 20명 약 96만원 (인지대 28,800원 + 송달료 회당 5,500원) |
| 법원 개인회생 · 변호사 수임료 | 통상 **200~300만원** (사무실별 차이 큼) |
| 법률구조공단 | 중위 125% 이하면 그 **회생 신청서 작성을 무료로** 지원 |

### 2. 실직자에게 "퇴사한다면 사유가?" — 맞습니다

```js
{k:'why', need:c=>c.work.on||c.work.insured>0, …}   // 이미 퇴사한 사람도 걸림
{k:'why', need:c=>c.work.on&&!c.work.quit, …}       // 재직 중이고 퇴사 계획이 없을 때만
```
이직 사유는 이직확인서에 있어 **고용보험 연동으로 들어옵니다.** 물어볼 일이 아닙니다.
최기준의 계획 문답이 3개 → **2개**(창업 · 이사)로 줄었습니다.

### 3. 유형 패널에서 할 일로 가는 버튼 — 넣었습니다

`감면으로 아끼는 것` 을 펼치면 각 제도 아래에 `준비물 보러 가기 ›` 가 붙습니다.
기존 `jumpTo('todo', …)` 를 그대로 씁니다 — 목표 항목이 펼쳐진 채로 열리고 깜빡입니다.

### 4. 직장 없고 연체 74일인데 전세대출 2억이 "가능" — 맞습니다

요건(무주택·소득)만 보고 **신용 상태를 안 봤습니다.** 정책자금이라도 연체 중에는
신규 대출 심사를 통과하기 어렵습니다. 공통 가드를 넣었습니다.

```js
const loanBlock=c=> c.credit.arrears>0
  ? NO(`현재 연체 ${c.credit.arrears}일 · 연체 중에는 신규 대출 심사를 통과하기 어렵습니다 · 채무조정이 먼저입니다`)
  : null;
```

적용: 중기청 전월세 · 버팀목 · 혁신창업사업화자금 · 청년전용창업자금 · 소상공인 정책자금 ·
경영안정자금 · 성장기반자금 (7건).
**새출발기금과 주택연금에는 적용하지 않았습니다** — 새출발기금은 신규 대출이 아니라 채무조정이고,
연체자야말로 대상입니다. 같은 `type:'loan'` 이라고 일괄 적용하면 정반대가 됩니다.

### 5·6. 분야 바로가기 상시 노출 + 성격별/분야별 세그먼트 탭

세로로 계속 쌓여서 부담스럽다는 지적. 두 블록을 **한 번에 하나만** 보이게 했습니다.

```
[ 성격별로 보기 | 분야별로 보기 ]   ← sticky 세그먼트
```

- 기본은 `성격별` · `S.tab` 으로 전환
- `분야별` 탭에서 **분야 바로가기 그리드가 접힘 없이 바로 보입니다** (`<details>` 제거)
- `판정 근거 보기 ›` 로 넘어오면 `jumpTo` 가 `S.tab='sector'` 로 자동 전환
- 세그먼트는 `position:sticky; top:118px` — 15개 분야를 내려가다가도 바로 되돌아올 수 있습니다

한 화면에서 보이는 세로 길이가 절반으로 줄었습니다.

